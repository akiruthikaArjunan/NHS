First — add the ThreadLocal declaration
Inside your DriverFactory class, between the { and }, type:
javaprivate static final ThreadLocal<WebDriver> driverHolder 
    = new ThreadLocal<>();


Now add the createDriver() method
This is the most important method — it creates and opens the browser.
Type this below the ThreadLocal line:


public static WebDriver createDriver(String browser, boolean headless) {
    WebDriver driver;
    
    if (browser.equalsIgnoreCase("firefox")) {
        WebDriverManager.firefoxdriver().setup();
        driver = new FirefoxDriver();
    } else {
        WebDriverManager.chromedriver().setup();
        ChromeOptions options = new ChromeOptions();
        if (headless) {
            options.addArguments("--headless=new");
        }
        options.addArguments("--window-size=1920,1080");
        driver = new ChromeDriver(options);
    }
    
    driver.manage().window().maximize();
    driverHolder.set(driver);
    return driver;
}


In simple words the whole method does this:
Someone calls createDriver("chrome", false)
     ↓
Download ChromeDriver automatically
     ↓
Open Chrome browser, maximise it
     ↓
Store it in ThreadLocal locker
     ↓
Return the browser

Now add the getDriver() method

This method simply gets the browser that was stored in the ThreadLocal locker.
Type this below the createDriver() method:
javapublic static WebDriver getDriver() {
    WebDriver driver = driverHolder.get();
    if (driver == null) {
        throw new IllegalStateException(
            "Driver not initialised. Call createDriver() first.");
    }
    return driver;
}
Before you type — understand what it does:
Someone calls getDriver()
     ↓
Look inside the ThreadLocal locker
     ↓
If locker is EMPTY → throw an error with a helpful message
If locker has a browser → return it

Now add the final method — quitDriver()
This method closes the browser and cleans up the ThreadLocal locker.
Type this below the getDriver() method:
javapublic static void quitDriver() {
    WebDriver driver = driverHolder.get();
    if (driver != null) {
        driver.quit();
        driverHolder.remove();
    }
}
Before you type — understand what it does:

Someone calls quitDriver()
     ↓
Check if there is a browser in the locker
     ↓
If YES → close the browser (driver.quit())
       → empty the locker (driverHolder.remove())
If NO  → do nothing

Understanding BasePage structure first
BasePage needs two things at the top:

driver — the browser, so every page can control it
wait — a timer that waits for elements to appear on screen

Why do we need wait?
Websites load slowly sometimes. If we try to click a button before it appears — the test crashes!
WebDriverWait says:

"Wait up to 15 seconds for this element to appear"
If it appears sooner — great, continue immediately
If it never appears in 15 seconds — fail with a clear error


First — add the constructor and variables
Inside your BasePage class type:
javaprotected final WebDriver driver;
protected final WebDriverWait wait;

protected BasePage(WebDriver driver) {
    this.driver = driver;
    this.wait = new WebDriverWait(driver, Duration.ofSeconds(15));
}

Now add the click() helper
What it does:

Waits for an element to be clickable (visible AND enabled)
Then clicks it

Type this below typeText():
javaprotected void click(By locator) {
    WebElement element = wait.until(
        ExpectedConditions.elementToBeClickable(locator));
    element.click();
}
Notice the difference from waitForVisible():

visibilityOfElementLocated — just checks if element is visible
elementToBeClickable — checks if element is visible AND can be clicked

A button can be visible but disabled — elementToBeClickable handles that!

Now add the isVisible() helper
What it does:

Checks if an element is visible on the page
Returns true if visible
Returns false if not visible — without crashing!

Type this below getText():
javaprotected boolean isVisible(By locator) {
    try {
        return wait.until(
            ExpectedConditions.visibilityOfElementLocated(locator))
            .isDisplayed();
    } catch (Exception e) {
        return false;
    }
}
Why the try/catch?

If the element is NOT on the page — Selenium throws an error
Without try/catch — your test would crash
With try/catch — it simply returns false instead
Much safer! ✅

waitForVisible() vs isVisible()

waitForVisible() — "I EXPECT this element to be there"
Looks for the element...
If found → returns it ✅
If NOT found after 15 seconds → CRASHES with an error ❌
Use it when: You are sure the element should be there.
Example:

You just clicked Search
You EXPECT results to appear
If they don't — something is genuinely wrong
You WANT it to crash and tell you!


isVisible() — "I'm just CHECKING if it's there"
Looks for the element...
If found → returns TRUE ✅
If NOT found → returns FALSE (no crash!) ✅
Use it when: The element might or might not be there.
Example:

Checking if a cookie banner appeared
It might appear, it might not
You don't want your test to crash just because there's no cookie banner!


Real life comparison
Think of it like knocking on a door 🚪
waitForVisible() is like:

Knocking and expecting someone to answer
If nobody answers → you call the police (throws error)
Used when someone MUST be home

isVisible() is like:

Knocking and checking if someone is home
If nobody answers → you just walk away (returns false)
Used when they might or might not be home

Now add the isPresent() helper
What it does:

Checks if an element exists in the page code
Returns true or false
Does NOT wait at all

Type this below isVisible():
javaprotected boolean isPresent(By locator) {
    return !driver.findElements(locator).isEmpty();
}
Understanding it:

driver.findElements(locator) — finds ALL matching elements
Returns a list — if nothing found, list is empty
.isEmpty() — checks if list is empty
! — flips it — so returns true if list is NOT empty
